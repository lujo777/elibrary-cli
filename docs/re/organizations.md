# Организации: orgs.asp, org_profile.asp, org_about.asp, org_items.asp

Файлы области: `models/organizations.py`, `queries/organizations.py`, `parsers/organizations.py`,
`data/orgs_options.json`, `tests/test_organizations.py`.

Источники: фикстуры `tests/fixtures/html/orgs_form.html`, `orgs_results_mgu.html`,
`org_profile_2541.html` (сохранены 13.10.2026), полный оригинал формы `scratchpad/re/pages/orgs.html`
(все варианты городов/регионов), архивные снимки из research (`wayback/org_about_14074.html` — 2024,
`wayback/org_items_102.html`, `wayback/org_profile_1181.html` — 2025). Ни одного запроса к elibrary.ru при
разработке не отправлялось.

## 1. Поиск организаций — `POST /orgs.asp`

### Форма

`<FORM method=post name="results" action="orgs.asp">` открывается **прямо внутри `<table>`**, поэтому
HTML5-парсер (Lexbor) оставляет элемент `form` пустым — поля нельзя искать как `form input`.
Порядок полей берётся по порядку документа (`parsers.organizations._form_controls`).

Поля в порядке браузера (проверено по фикстуре и по живому запросу `orgs_mgu.meta.json`):

| Поле | Тип | Значения |
|---|---|---|
| `pagenum` | hidden | `org_search()` ставит `""`, `goto_page(N)` — `N` |
| `orgname` | text | слова названия |
| `town` | select | точное название города (`Москва`), `""` — любой; 16 098 вариантов |
| `regionid` | select | id региона, `0` — любой; 2 207 вариантов |
| `countryid` | select | ISO3 (`RUS`), `""` — любая; 230 вариантов |
| `sortorder` | select | `0` по названию, `1` по городу, `3` по числу статей, `4` по числу цитирований (`2` в форме нет) |
| `order` | select | `0` по возрастанию, `1` по убыванию |

JS `onChange` у `sortorder` выставляет порядок по умолчанию: для `0`,`1` — `0`, для `2`,`3`,`4` — `1`.
`OrgQuery.order=None` повторяет это поведение (`OrgQuery.effective_order`).

Живое тело запроса для фикстуры `orgs_results_mgu.html`:
`pagenum=&orgname=московский+государственный+университет&town=&regionid=0&countryid=&sortorder=3&order=1`
— `build_org_search_form(OrgQuery(name=..., sort="publications"))` даёт ровно его (тест
`test_search_form_matches_live_request`).

**Пагинация без состояния на сервере**: `goto_page(N)` отправляет всю форму заново с `pagenum=N`
(в ответе форма заполнена текущим запросом). 20 организаций на страницу.

Ссылки карточки организации (`org_about.asp`) показывают, что `orgs.asp` принимает и GET-параметры
`countryid`, `regionid`, `town`, `vedomid` (ведомство) — `vedomid` в форме нет, в `OrgQuery` не добавлен.

### Результаты

* Счётчик: `Всего найдено организаций: <b>23</b> из <b>123983</b>. Показано на данной странице: с <b>1</b> по <b>20</b>.`
  → `total`, `total_in_database`, `page`/`per_page` (`_TOTAL_ORGS_RE`, `_RANGE_RE`).
* Таблица `table#restab`: первая строка — заголовки (`№ | Название организации | Город | Публ. | Цит.`),
  строки организаций `tr#a<ORGID>`. Колонки сопоставляются **по тексту заголовка**; неизвестные колонки
  попадают в `OrgHit.extra` (`Страна`/`Регион`, если появятся, — в `country`/`region`).
* В строке: название → `org_about.asp?orgsid=ID` (`OrgHit.url`), число публикаций → `org_items.asp?orgsid=ID`
  (`publications_url`, `title="Список публикаций данной организации в РИНЦ"`, т.е. число — публикации в
  РИНЦ), иконка `stat.gif` → `org_profile.asp?id=ID` (`profile_url`), цитирования →
  `cit_org_items.asp?id=ID` (`citing_url`).
* Пейджер: `javascript:goto_page(N)`; `pages` = max(ceil(total/20), max N в ссылках).
* Скрытое поле `pagenum` в ответе = номер показанной страницы (`1`, хотя отправлено `""`).
* Запрос «эхом» читается из формы (`orgname` value, `selected` у select-ов) → `SearchPage.query`,
  если `query` не передан в парсер.

Страница без условий (`orgs_form.html`: «Укажите условия запроса…») разбирается как пустой результат
(`total=0`, `pages=0`). Как выглядит ответ «ничего не найдено» — неизвестно (нет фикстуры); парсер вернёт
пустой список, если на странице есть форма `orgname`.

  (в 2025 г.: `… - Анализ публикационной активности`) → `OrgProfile.name` (с нормальным регистром).

| ЦИТИРОВАНИЯ ПУБЛИКАЦИЙ ЗА 5 ЛЕТ ПО ОБЛАСТЯМ ЗНАНИЙ | `citations_by_field` | то же |

Сопоставление строк «ОБЩИЕ ПОКАЗАТЕЛИ» с полями: Число публикаций на elibrary.ru → `publications`;
… в РИНЦ → `publications_rinc`; …, входящих в ядро РИНЦ → `publications_core`; Число цитирований
публикаций на elibrary.ru → `citations`; … в РИНЦ → `citations_rinc`; Число цитирований из публикаций,
входящих в ядро РИНЦ → `citations_from_core`; Индекс Хирша по всем публикациям / в РИНЦ / по ядру →
`h_index`/`h_index_rinc`/`h_index_core`; g-индекс, i-индекс; Число авторов → `authors_count`; Число
авторов, зарегистрированных в Science Index → `authors_registered`. 5 лет: публикации (все/РИНЦ/ядро),
«Число цитирований в РИНЦ» → `citations_rinc_5y`, средневзвешенный ИФ → `impact_factor_5y`.
Сравнение по названию без учёта регистра и `ё`.

Числа: целые без разделителей тысяч (`4303477`), дробные с запятой (`1,339`); парсер понимает и пробелы
как разделители тысяч. Подсказки к показателям (длинные тексты) включаются только при
`parse_org_profile(..., with_descriptions=True)` — иначе JSON профиля МГУ ~68 КБ.

Правая панель: «Дата обновления показателей организации: 20.06.2026» → `updated`; остальные пункты с
иконкой `but_orange_!.gif` → `notes`. Ссылки «ИНСТРУМЕНТЫ»: `org_items.asp?orgsid=ID`,
`cit_org_items.asp?id=ID`.

Адреса, ведомства, типа, сайта, ROR/ИНН на этой странице **нет** — они в карточке `org_about.asp`.

## 3. Карточка организации — `GET /org_about.asp?orgsid=ID` (не проверено на 2026)

Фикстуры 2026 г. нет; парсер `parse_org_about` написан по снимку 2024 г. (`<title>Информация об
организации</title>`, заголовок «КАРТОЧКА ОРГАНИЗАЦИИ», `input[name=orgsid]`). Пары ячеек в одной строке:
метка `td[bgcolor=#dddddd]` + значение `td[bgcolor=#eeeeee]` (запасной вариант — метка с `:` на конце).
Берутся только строки после заголовка «КАРТОЧКА» (в левой колонке сайта тоже есть `#dddddd`-ячейки).

| Метка | Поле |
|---|---|
| Полное название | `full_name` (и `name` карточки) |
| Название на англ. | `name_en` |
| Сокращение / Сокращение англ. | `abbreviation` / `abbreviation_en` |
| Страна (`orgs.asp?countryid=RUS`) | `country`, `country_code` |
| Регион (`orgs.asp?regionid=73`) | `region`, `region_id` |
| Город / Город на англ. | `town` / `town_en` |
| Почтовый адрес / Адрес на англ. / Юридический адрес | `address` / `address_en` / `legal_address` |
| Ведомство (`orgs.asp?vedomid=8`) | `department`, `department_id` |
| Тип | `org_type` |
| Головная/вышестоящая организация (ссылка `orgsid`) | `parent_name`, `parent_id` (в снимке не было — предположение) |
| Телефон / E-mail (`mailto:`) / Факс / WWW | `phone` / `email` / `fax` / `website` (`email` — только метка ровно «E-mail» / «Эл. почта» / «Электронная почта») |
| ИНН, ОГРН, КПП, ROR, GRID, … | `identifiers` (в снимке не было — предположение) |
| остальные (Представитель (подписка), Должность, …) | `extra` |

Пустые значения (например, пустой «Факс») пропускаются. `OrgProfile.merge(card)` дополняет профиль
полями карточки (значения профиля приоритетны, словари объединяются).

Конфиденциальность (13.10.2026): `email` — публичный адрес самой организации. Метки вида «E-mail
представителя» больше не попадают в `email` (регулярка привязана к целой метке), а из значений `extra`
адреса e-mail вырезаются (`parsers.journals.strip_emails`): «Петров П.П. (petrov@…)» → «Петров П.П.»,
значение, состоящее только из адреса, отбрасывается. Имя и должность представителя остаются, как на странице.

Короткая ссылка `https://elibrary.ru/<ROR>` открывает профиль организации (см. research), т.е. ROR у
elibrary есть, но на страницах 2026 г. мы его не видели.

## 4. Публикации организации — `org_items.asp?orgsid=ID`

Живая страница сохранена 13.10.2026: `org_items_18078.html` («Томский политехнический техникум», Томск,
49 публикаций, одна страница). Разбор подтверждён тестами `tests/test_live_fixtures.py`: счётчик «Всего
найдено <b>49</b> публикаций с общим количеством цитирований: <b>12</b>. Показано на данной странице: с 1
по 49.» → `total=49`, `total_citations=12` (сумма цитирований строк — тоже 12), пейджера нет → `pages=1`;
hidden `orgsid=18078`, `show_refs=0`, `hide_doubles=1`, выбраны `show_option=0` (РИНЦ), `show_sotr=0`,
`sortorder=0`, `order=1`, `orgdepid=0`; строки `tr#arw<ITEMID>` с номерами 1…49, 45 докладов («В сборнике:
… конференции …») и 4 статьи. Исправлений парсера не потребовалось.

Макет совпадает с `author_items.asp` (фикстура `author_items_3771.html`) и снимком
`org_items_102.html` (2025): заголовок `div[style*=540px]` (название, город), форма `results` с
`orgsid`, `show_refs`, `hide_doubles`, select-ы `orgdepid` (подразделение), `show_option`, `show_sotr`,
`sortorder`, `order` и мультивыбор фильтров (тематика/журналы/организации/авторы/годы/типы/роли, загружаются
JS), счётчик `Всего найдено <b>143</b> публикации с общим количеством цитирований: <b>635</b>. Показано на
данной странице: с 1 по 100.`, строки `tr#arw<ITEMID>` в `table#restab` (разбирает `parsers.rows`), пейджер
`goto_page(N)`, 100 строк на страницу. Заголовок страницы: `<НАЗВАНИЕ> - Список публикаций организации`.

`build_org_items_request(org_id, page)` — **предположение**: `GET /org_items.asp?orgsid=ID[&pagenum=N]`
(+ необязательные `show_option`, `show_sotr`, `show_refs`, `pubyear=2021|2022`, `sortorder`, `order` — имена
из ссылок профиля и из формы). Браузер листает POST-ом всей формы `results`; GET с `pagenum` используют
сторонние скрейперы (crawlic-stud/elibrary-parser), classic ASP читает `Request()` из строки запроса и тела.
Что показывает список по умолчанию (`show_option`/`show_sotr`), без фикстуры неизвестно; ссылка из поиска
подписана «Список публикаций данной организации в РИНЦ».

Значения `show_option`: `1` все на elibrary.ru, `0` РИНЦ, `2` ядро РИНЦ, `5` ВАК, `3` RSCI, `9` WoS CC,
`10` Scopus, `4` WoS или Scopus, `6`/`7`/`8` ИФ РИНЦ > 0,02/0,1/0,3, `11` с DOI, `12` с ISBN (в ссылках
профиля встречаются также `26` Белый список и `36` БС ЕГПНИ). `show_sotr`: `0` явно указана организация,
`1` сотрудники в период работы, `2` нынешние сотрудники. `sortorder`: `0` дата выпуска, `1` название,
`2` год и первый автор, `5` первый автор, `3` цитирования, `4` дата размещения.

У крупных организаций последние страницы списка отвечают > 60 с (см. reverse-engineering.md). Поэтому
`get_organization_publications` ждёт ответа `ELIBRARY_HEAVY_TIMEOUT` секунд (по умолчанию 180, не меньше
`ELIBRARY_TIMEOUT`). После таймаута чтения запрос не повторяется автоматически: сервер уже считает
страницу, и повтор стоил бы второго тяжёлого запроса (см. `docs/re/auth.md`).

## 5. Справочник `data/orgs_options.json`

Сгенерирован `parse_org_form_options()` из полного `orgs.html` (13.10.2026). Формат как у
`authors_options.json`: ключи — имена полей формы, элементы `{"value", "label", "count"}`:
`countryid` (230, ISO3), `regionid` (2 207, id региона), `sortorder` (+ `key`, `default_order`),
`order` (+ `key`). Список городов (16 098) **не включён** — в `_meta.town_count`/`town_note`; город
передаётся строкой. Названия регионов не уникальны (`Central`, `Punjab`, …) — `resolve_region` при
точном совпадении берёт вариант с наибольшим `count`. `resolve_country`/`resolve_region` принимают коды
и русские названия (`Россия` → `RUS`, `Москва` → 73, `Новосибирская область` → 51).

## 6. Не проверено / открытые вопросы

* `org_about.asp` 2026 г. — без фикстуры; парсер протестирован на синтетическом HTML по архивному снимку.
  `org_items.asp` проверен на живой странице (`org_items_18078.html`, одна страница); многостраничный список
  (пейджер `goto_page(N)`) организации вживую не сохранялся.
* Ответ `orgs.asp` «ничего не найдено» и `org_profile.asp` с несуществующим id — неизвестны
  (`NotFound` бросается, если на странице анализа нет ни шапки, ни разделов).
* В списках публикаций строки «из списков цитируемой литературы» (`tr#brw<ID>`, без ссылки `item.asp`,
  при `show_refs=1`) общий `parsers.rows` пропускает (их возвращает `parse_reference_rows`); блок
  «Версии:» (переводные версии) после QA больше не попадает в `source`: id версий — в
  `PublicationHit.versions`.

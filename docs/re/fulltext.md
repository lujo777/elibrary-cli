## 1. Устройство пакета

| Модуль | Что делает |
|---|---|
| `fulltext/__init__.py` | модели `FulltextRequest`, `FullText`, `FulltextAttempt`; `get_fulltext()` — перебор источников, кэш текста, постраничная выдача; `slice_text()` |
| `fulltext/net.py` | `ExternalHTTP` — HTTP-клиент для **не**-elibrary хостов (вежливость, кэш, лимит размера, антибот-предохранитель) |
| `fulltext/sources.py` | Crossref, Unpaywall, OpenAlex, DataCite, Handle, КиберЛенинка, страницы издателей; нечёткое сопоставление записей |
| `fulltext/pdf.py` | `extract_pdf_text()` — pypdf → (если текст «битый») pdfminer.six, очистка текста |
| `fulltext/elibrary.py` | ссылки на PDF на страницах elibrary, признак входа, скачивание PDF через `ElibraryHTTP` |

Порядок источников по умолчанию: `elibrary → cyberleninka → unpaywall → openalex → crossref →
publisher`. Меняется аргументом `sources=[...]` или переменной `ELIBRARY_FULLTEXT_SOURCES`
(через запятую; в `config.py` такого поля пока нет — см. «Открытые вопросы»). Первый текст,
прошедший проверки качества, сохраняется и возвращается; каждая попытка записывается в
`FullText.attempts` (`source`, `status`, `detail`, `url`). Статусы: `ok`, `skipped`, `not_found`,
`no_match`, `rejected`, `login_required`, `blocked`, `error`, `info`. Если ничего не нашлось —
`NotFound` с перечнем попыток в тексте и в атрибуте `exc.attempts` (список словарей).

## 2. elibrary.ru

### Что известно

* Аноним: функции `load_article(iid)`, `file_article(fid, filenum)`, `url_article(idid, urlnum)`,
  `order_item()` в JS страницы только показывают `alerts("Для доступа к полному тексту необходимо
  вначале войти в библиотеку!")` и раскрывают форму входа. Вызовы: `javascript:load_article(ID)`
  (иконка `download_green.png` «Доступ к полному тексту открыт» из `ispdf.asp?itemid=ID`) и
  `javascript:file_article(ID, 1)` («Загрузить: Полный текст (PDF)» на странице патента 47430099).
* Платная статья (46371463): `javascript:order_item()` + «Приобрести эту публикацию за 455 руб.»;
  `url_article(46371463, 1)` — «Версия на другом языке (EN)».
* Вошедший читатель (страница `query_results.asp`, сохранённая пользователем в 2025 г., найдена в
  стороннем репозитории): `load_article(id)` ставит `document.forms["results"].action =
  "full_text.asp?id="+id` и отправляет форму в новое окно; `url_article` — `url_article.asp` с
  полями `did`, `urlnum`. Сторонние скрипты (selenium, 2016–2020) открывали
  `GET http://elibrary.ru/full_text.asp?id=<ID>` после входа. Транслятор Zotero (закомментированный
  код) искал в ответе `full_text.asp` ссылку `http://elibrary.ru/download/….pdf`; в списках
  литературы встречаются адреса вида `https://elibrary.ru/download/elibrary_<ID>_<N>.pdf`, где `N` —
  серверный номер файла (из ID не выводится).
* `file_article` для вошедших **нигде не описан**. По аналогии с `url_article` и скрытыми полями
  формы `results` (`fileid`, `filenum`, `urlnum`) пробуется
  `file_article.asp?fileid=<fid>&filenum=<n>` (не проверено), затем документированный
  `full_text.asp?id=<id>`.

### Реализация

* `find_elibrary_pdf_links(html, item_id=None)` — порядок: прямые `/download/….pdf` (в `href`,
  `meta refresh`, JS `window.open`/`location`), прочие `.pdf`/`full_text.asp` на elibrary.ru,
  `full_text.asp?id=<id>` для каждого **вызова** `load_article(<id>)` (сначала `item_id`),
  `file_article.asp?fileid=…&filenum=…`. Определения функций (`function load_article(iid)`) не
  считаются вызовами. Ссылки на чужие хосты отбрасываются.
* `is_logged_in(html)` / `session_user(html)` — по `#win_session`: «Имя пользователя:
  Незарегистрированный пользователь» → аноним; «Имя пользователя: <логин>» → вошёл. Без блока сессии
  (фрагменты вроде `ispdf.asp`, ответы `full_text.asp`) — `False`. «Личный кабинет» и «Закрыть
  сессию» есть и у анонимов — признаком не являются (то же в `docs/re/auth.md`).
* `fulltext_status(html)` — `available`, `paid`, `price_rub`, `links`.
* `download_elibrary_pdf(http, item_id, item_html, dest_dir)`: аноним → `LoginRequired` с
  инструкцией (`elibrary auth login` / `elibrary auth cookies` + `elibrary auth check`); нет ссылок →
  `NotFound` (для платных — с ценой). Иначе до 4 загрузок через `http.download` (троттлинг, бюджеты,
  предохранитель капчи — общие с остальным CLI): PDF распознаётся по сигнатуре `%PDF` и размеру
  > 1000 байт, HTML-ответ просматривается на `/download/….pdf` (второй шаг) и на «необходимо вначале
  войти» (`LoginRequired`). 404 по одной ссылке — переход к следующей. Готовый файл
  `dest_dir/elibrary_<id>.pdf` переиспользуется без запроса.
* В `get_fulltext` источник `elibrary` **не тратит запросов на анонимную сессию**: он работает,
  только если в состоянии `http.state["account"]` записан пользователь (это делают `auth.login()` и
  `auth.check_session()`) или в кэше уже лежит страница публикации, показанная вошедшему читателю.
  Если кэшированная страница анонимная, а `account` есть — страница запрашивается заново
  (`cache_ttl_hours=0`), и **полученная страница вошедшего читателя записывается в кэш** под тем же
  ключом (`GET` + URL карточки, срок `TTL_ITEM`) вместо анонимной копии. Поэтому повтор вызова (платная
  статья, нет PDF, ошибка скачивания — текст в таком случае не кэшируется) и каждая следующая
  публикация пакета (`zotero add --with-pdf`) уже не тратят запрос к item.asp. Анонимный ответ (сессия
  истекла) в кэш не пишется — при следующем вызове страница снова запрашивается.

### 3.1. КиберЛенинка: адрес статьи по названию

Путь страницы — `/article/n/<slug>`, где `slug` детерминированно получается из названия статьи
(`sources.cyberleninka_slug`, `cyberleninka_candidate_urls`):

1. Теги и сущности удаляются, NFKC, нижний регистр.
2. Кириллица транслитерируется по таблице `CL_TRANSLIT`: а a, б b, в v, г g, д d, е e, **ё yo**, ж zh,
   з z, и i, **й y**, к k, л l, м m, н n, о o, п p, р r, с s, т t, у u, ф f, **х h**, **ц ts**, ч ch,
   ш sh, **щ sch**, **ъ —**, **ы y**, **ь —**, э e, ю yu, я ya («ый» → `yy`: `sovremennyy`, `novyy`).
   Латиница и цифры остаются (`SARS-CoV-2` → `sars-cov-2`, `60С2ХФА` → `60s2hfa`), латинские буквы с
   диакритикой упрощаются (не проверено), «і ї є ґ ў» → i yi ye g u (догадка), `№` — разделитель
   (догадка).
3. Любая последовательность прочих символов (пробелы, точки, запятые, кавычки, скобки, дефисы,
   тире) — один `-`: `4.0` → `4-0`, `Б. Н.` → `b-n`, `по-разному` → `po-raznomu`; `ь`/`ъ` разделителями
   не являются (`объекта` → `obekta`, `сеть` → `set`).
4. Длина — не больше **131** символа: слаг длиннее обрезается после последнего целого слова,
   умещающегося в 131 символ. Константа выведена из примеров: целиком остаются слаги длиной 130
   (`vliyanie-terapii-rituksimabom-…-artritom`) и 131 (`hemoreaktomnyy-skrining-…-osnova-dlya`, дальше
   шло бы `-prinyatiya`), а 132-символьный `…-perspektivnye-napravleniya` обрезан до `…-perspektivnye`.
   Гипотеза «обрезается русское название до N символов» опровергнута: примеры требуют N ≥ 129
   («САХАРНЫЙ ДИАБЕТ В РОССИЙСКОЙ ФЕДЕРАЦИИ: … 2010–2022 ГГ.») и N ≤ 124 («ОСОБЕННОСТИ
   РЕВАСКУЛЯРИЗАЦИИ МИОКАРДА …») одновременно.
5. Статьи с одинаковым слагом получают суффиксы `-1`, `-2`, … («НЕЙРОННЫЕ СЕТИ» Ксенофонтова —
   `neyronnye-seti-1`; «Новый институциональный подход…» — `…-shemy-1`).

Проверка: тест `test_cyberleninka_slug_matches_every_saved_link` сверяет правило со всеми 8 парами
«название → ссылка» из `cyberleninka_search_*.json`, ссылкой OpenAlex и примером карточки 54076582;
`test_cyberleninka_slug_matches_public_links` — с 31 публичным адресом (в том числе 14 обрезанных).
Единственное найденное исключение — «…(ценностно-мотивационный аспект)» →
`…tsennostno-motivatsionnyi-aspekt` (вероятно, в названии на сайте «и» вместо «й»); в тесты не
включено.

Порядок источника `cyberleninka` в `get_fulltext`:

1. DOI с префиксом `10.24412` → DataCite → страница статьи (совпадение по DOI);
2. ссылка на копию из OpenAlex (если источник `openalex` уже отработал);
3. страницы `<slug>`, `<slug>-1`, `<slug>-2` (не больше 3 запросов). Страница принимается, только
   если её `citation_title`/автор/год проходят `match_score` (порог 0.9 при совпадении фамилии, 0.95
   без авторов); иначе — попытка `rejected` и следующий кандидат. **404 на `<slug>` завершает
   перебор**: дубликаты нумеруются после первой статьи с этим слагом, значит, `-1`/`-2` тоже нет —
   промах стоит один запрос;
4. только при `ELIBRARY_CYBERLENINKA_SEARCH=1` — поиск через `/api/search` (как раньше);
5. иначе — `no_match` «на КиберЛенинке нет статьи с таким названием и авторами».

Ссылки на PDF/просмотрщик КиберЛенинки из Unpaywall/OpenAlex/страниц издателей
(`…/pdf`, `….pdf`, `…/viewer`) превращаются в адрес HTML-страницы (`cyberleninka_page_url`); сам PDF
не скачивается никогда (`ExternalHTTP.download` отказывает для cyberleninka.ru, в том числе после
перенаправления).

Ограничения: если на elibrary в названии «е», а на КиберЛенинке «ё» (или наоборот), слаг не совпадёт;
то же при опечатках и других расхождениях названий. Тогда помогают DOI-путь, OpenAlex или явное
согласие на поиск.

### КиберЛенинка: соседние статьи

КиберЛенинка распознаёт целые страницы PDF выпуска, поэтому текст может начинаться с конца
предыдущей статьи и заканчиваться началом следующей. `_trim_neighbours`:

1. Ищется абзац (или два соседних вместе), совпадающий с названием (страницы или запроса):
   нормализованное равенство, сходство ≥ 0.9 или начало абзаца с названием.
2. Начало сдвигается назад максимум на 3 абзаца вида `УДК…`, `UDC…`, `ББК…`, `DOI: 10.…`.
3. Голова отбрасывается, **только если** похожа на конец другой статьи (есть «Ключевые слова»,
   «Key words», «Список литературы», «Библиографический список», «References», «Литература»).
4. Конец — первый абзац `УДК/UDC/ББК/DOI` не ближе 5 абзацев к названию.

На фикстуре «Нейроны в нейронных сетях»: 103 абзаца, отрезано 6 в начале (англ. аннотация
предыдущей статьи) и 10 в конце («УДК 654.022 / DOI …-443-449 ОСОБЕННОСТИ РАДИОКАНАЛОВ…»);
остаётся 13 315 символов. `trimmed_head`/`trimmed_tail` возвращаются в `CyberLeninkaArticle`.

### Правила использования КиберЛенинки

`robots.txt` (получен 13.10.2026) для `User-Agent: *` запрещает: `/search/*`, `/search?`, `/user/*`,
`/donate/*`, `/article/n/*/viewer`, `/article/v/*`, `/api/`, `/article/n/*/pdf`, `/article/n/*.pdf`,
`/viewer_images/*`; страницы статей `/article/n/<slug>` разрешены. Условия (§6.2) запрещают
автоматический сбор без письменного согласия. Поэтому: только точечные запросы по инициативе
пользователя (одна статья — до 3 страниц), по умолчанию **никаких** `/api/`, `/search` и PDF, перед
страницей проверяется `robots.txt` (§7), пауза 3 с, кэш (страница — 30 дней, `robots.txt` — 24 ч),
остановка на странице «Вы точно человек?» (15 минут на хост). Поиск через API включается только явно
(`ELIBRARY_CYBERLENINKA_SEARCH=1` / `Settings.cyberleninka_search`) и **нарушает `robots.txt`** —
это осознанный выбор пользователя. Источник можно исключить
(`ELIBRARY_FULLTEXT_SOURCES=unpaywall,openalex,crossref,publisher`).

## 4. Сопоставление записей

* `normalize_title`: удаление тегов и сущностей, NFKC, casefold, `ё→е`, пунктуация → пробел; в
  словах со смешанной письменностью латинские двойники приводятся к кириллице (или наоборот, по
  большинству букв): `Hейроны` (латинская H) = `нейроны`.
* `title_similarity` = среднее `difflib.SequenceMatcher.ratio` и Жаккара по словам. Оба штрафуют
  лишние слова: «Нейронные сети» vs «Нейронные сети в медицине» = 0.61; «…обучения нейронных
  сетей» vs «…обучения сверточных нейронных сетей» = 0.87 (ниже порога).
* Фамилии (`surname`): «Петров В.А.», «В.А. Петров», «Панарин Владимир Михайлович» (кириллица —
  первое слово), «Vladimir V. Ryazanov» (латиница — последнее слово), «Ryazanov, Vladimir V.» (до
  запятой), «Vasiliev Alexander Petrovich» (латиница с отчеством — первое слово). Сравнение по
  транслитерации (`х→kh→h`, `ий/ый→y`…) с порогом сходства 0.8; запасной вариант — любое слово
  имени кандидата.
* `match_score`: одинаковый DOI → 1.0, разные DOI → 0; иначе год ±1, при наличии авторов хотя бы одна
  фамилия должна совпасть (одинаковые общие названия — частое явление: «НЕЙРОННЫЕ СЕТИ»
  Ксенофонтова 2020 г. и других), порог названия 0.9; если авторов сравнить нельзя — 0.95.
* Проверка PDF (`title_in_text`): ≥ 60 % значимых слов названия (RU или EN) в первых 15 000
  символах; иначе PDF отклоняется как «другой документ или заглушка». Плюс ≥ 800 символов текста и
  ≥ 100 символов на страницу (иначе — скан без текстового слоя).

## 5. Извлечение текста из PDF (`pdf.py`)

* Сначала pypdf, при «битом» тексте — pdfminer.six; выбирается вариант с меньшей «плохостью»
  (доли относительно порогов), если он не короче 70 % первого. Импорт ленивый; нет обоих —
  `DependencyMissing("pdf", "pypdf")`.
* «Битость»: доля коротких (1–3 буквы) строчных кириллических «слов», которых нет в словаре
  коротких слов и сокращений (заглавные аббревиатуры вроде «КТ», «ИБС» не считаются), после
  склейки переносов; порог 1.8 %. Калибровка на трёх PDF из исследования: чистые движки
  0.1–0.6 %, pypdf на PDF КиберЛенинки 2.2 % («Нейрон ы», «инф орматики»), pypdf на Эко-Вектор и
  Elpub 1.0–1.3 % (приемлемо), «табличные» режимы с перемешанными колонками 2.1–2.7 %. Mojibake:
  U+FFFD, частная область Unicode, управляющие символы, `(cid:N)` (×5), пары UTF-8-как-cp1252
  («Ð¿Ñ€»), порог 2 %.
* Очистка: `\r\n`, `\x02` (pdfium), NBSP, BOM, мягкие переносы; склейка переносов `слово-\nслово`
  (в т.ч. pypdf-вариант «атероген -\nность»), но сохраняются «из-за», «кто-то», «по-прежнему»,
  «во-первых», «сердечно-сосудистых», «Санкт-Петербург» (заглавная буква); «сети -\nэто» остаётся
  тире. Колонтитулы: строки (цифры нормализуются), повторяющиеся на ≥ 40 % страниц (минимум на 3);
  номера страниц — среди первых/последних двух строк. Абзацы: пустая строка, пункт списка, короткая
  строка с точкой в конце, короткая строка перед заглавной. Абзац, продолжающийся на следующей
  странице, склеивается. `page_markers=True` добавляет «[стр. N]».
* Проверено на реальных PDF (не в репозитории): КиберЛенинка 6 с. → pdfminer (pypdf отбракован),
  Elpub 15 с. и Эко-Вектор 13 с. → pypdf.

### 5.1. Пределы ресурсов («PDF-бомбы»)

PDF приходят с произвольных хостов (ссылки из Unpaywall/OpenAlex/Crossref и со страниц издателей).
Поток FlateDecode сжимается примерно 1000:1, поэтому файл в несколько мегабайт (в пределах
`ELIBRARY_MAX_DOWNLOAD_MB`) может распаковаться в гигабайты. Раньше pypdf останавливался на своём
пределе 75 МБ, страница выходила пустой («текст слишком короткий»), и файл передавался pdfminer.six,
который распаковывает потоки `zlib.decompress(data)` без ограничения (проверено: PDF 300 КиБ →
600 МиБ пика памяти). Теперь (`pdf.py`):

* **Бюджет распаковки на документ и движок**: поток — не больше `MAX_STREAM_BYTES` (32 МиБ),
  все потоки документа вместе — не больше `MAX_DECODED_BYTES` (200 МиБ). В pypdf — через его
  конфигурацию (`apply_configuration`, пределы `*_maximum_output_length` снижены до 32 МиБ) и обёртку
  `pypdf.filters.decode_stream_data`, которая считает каждый распакованный поток (объектные потоки,
  потоки содержимого, формы, шрифты). В pdfminer — заменители `zlib` (и `decompress`, и
  `decompressobj` — его использует «починка» повреждённых потоков), `lzwdecode`, `rldecode` и
  `ccittfaxdecode` в модуле `pdfminer.pdftypes`: распаковка идёт с `max_length` и обрывается на
  пределе, а не после полной распаковки. Заменители действуют только внутри `extract_pdf_text`
  (бюджет — `ContextVar`, вне его поведение библиотек не меняется; потоки разных задач не мешают
  друг другу).
* pdfminer строит на каждый символ объект раскладки (~1 КБ), поэтому на странице допускается не
  больше `MAX_PDFMINER_CHARS_PER_PAGE` (50 000) символов.
* **После срабатывания предела другой движок не запускается** (`PdfResourceLimit`, подкласс
  `ParseError`). Если до остановки уже прочитаны страницы с текстом, используются они (длинная книга
  обрезается, а не отбрасывается); страница, на которой сработал предел pypdf для одного потока,
  остаётся пустой, остальные читаются. Если текста нет — `PdfResourceLimit` с сообщением
  «Извлечение текста из PDF остановлено: … Возможно, это «PDF-бомба» …»; в `get_fulltext` такой PDF
  получает статус `rejected` («PDF отклонён: …»), файл удаляется, поиск идёт к следующему кандидату
  (то же теперь и для нечитаемого PDF — раньше `ParseError` обрывал весь источник со статусом
  `error`).
* Источники полного текста читают не больше `DEFAULT_MAX_PAGES` = 300 страниц (`page_count` по-прежнему
  — число страниц документа; проверка «символов на страницу» делится на число прочитанных страниц).
* Текст обрезается до `MAX_TEXT_CHARS` (3 000 000 символов).
* Не сделано: отдельный процесс с пределами памяти/времени (на Windows без сторонних средств нет
  простого способа); время разбора огромного, но не сжатого содержимого ограничено только размером
  файла.

## 6. Кэш и файлы

* Внешние ответы: `<cache_dir>/external-cache.sqlite3` (`PageCache`): API — 7 дней, HTML — 30
  дней, POST — ключ по URL + телу. `ELIBRARY_REFRESH=1` — мимо кэша, `ELIBRARY_OFFLINE=1` — только
  кэш (`OfflineCacheMiss`).
* Извлечённый текст: `<cache_dir>/fulltext/<ключ>.txt` + `<ключ>.json` для каждого ключа запроса
  (`elibrary-<id>`, `edn-<EDN>`, `doi-<sha1>`, или `title-<sha1>` если идентификаторов нет).
  Повторные вызовы с `offset` не делают запросов. `refresh=True` — заново.
* PDF: `download_dir` (по умолчанию `<cache_dir>/downloads`): `elibrary_<id>.pdf`,
  `<источник>_<ключ>_<hash>.pdf`; отклонённые PDF удаляются.

## 7. `ExternalHTTP` (`net.py`)

* User-Agent: `elibrary-cli/<версия> (+https://github.com/lujo777/elibrary-cli)`. E-mail из
  `ELIBRARY_CONTACT_EMAIL` (`; mailto:<e-mail>` в скобках) добавляется **только** для API, которые
  просят контакт: api.crossref.org, api.openalex.org, api.unpaywall.org, api.datacite.org
  (`CONTACT_HOSTS`; заголовок выставляется на каждом шаге перенаправления, так что редирект с API на
  другой хост e-mail не уносит). Страницы издателей, репозитории, хосты PDF, `robots.txt`,
  КиберЛенинка и Handle получают UA без e-mail (раньше он уходил всем — личный адрес исследователя
  попадал на любой хост из метаданных). Кроме того, Crossref/OpenAlex получают `mailto=` (polite
  pool), Unpaywall — `email=`.
* Пауза на хост: 1 с, cyberleninka.ru — 3 с (в пределах процесса; между процессами не делится).
  Один повтор при таймауте/сетевой ошибке/429/5xx с учётом `Retry-After` (не более 30 с).
* Ручные перенаправления (≤ 5), каждый шаг проверяется: только http/https, не elibrary.ru
  (`AssertionError` для прямого URL, `RedirectToElibrary` для перенаправления), не localhost и не
  частные IP-литералы.
* Защита от SSRF по DNS: адреса берутся из недоверенных метаданных и страниц издателей, а имя вроде
  `localtest.me` или `127.0.0.1.nip.io` (или DNS злоумышленника) указывает на 127.0.0.1 / 10.x /
  192.168.x / 169.254.169.254 — раньше такие URL запрашивались (сначала `robots.txt`, потом сама
  страница). Теперь перед каждым шагом (и перед запросом `robots.txt`) имя разрешается
  (`socket.getaddrinfo`); если **хотя бы один** адрес не глобальный (`ipaddress…is_global`, IPv4 в
  IPv6 проверяется как IPv4) — `PrivateAddress` («Запрос к … запрещён: имя … указывает на непубличный
  адрес …»), запрос не отправляется; `robots.txt` при этом тоже не запрашивается и «fail open» не
  срабатывает. Против DNS rebinding (имя «публичное» при проверке и локальное при соединении): в
  настоящем клиенте в пул соединений `httpx2` подставлен свой сетевой бэкенд
  (`_PublicOnlyBackend`), который сам разрешает имя, проверяет адреса и соединяется **с проверенным
  IP** (SNI и проверка сертификата — по имени хоста, как прежде). Имя, которое не разрешается при
  предварительной проверке, пропускается дальше (соединение и так не состоится; за прокси имена
  разрешает прокси). Запросы через прокси (`HTTPS_PROXY` и т.п.) соединяются с прокси пользователя —
  для них действует только предварительная проверка. С тестовым транспортом (`transport=`) проверка
  DNS выключена (`check_dns=None` → только для настоящей сети; в тестах `check_dns=True` и подменённый
  `socket.getaddrinfo`).
* Лимит ответа в памяти 50 МБ (`ResponseTooLarge`); скачивание файлов
  (`download`) — потоково через `.part` с пределом `ELIBRARY_MAX_DOWNLOAD_MB` (по умолчанию 100 МБ):
  при превышении загрузка прерывается, `.part` удаляется, `ResponseTooLarge` с русским сообщением.
  Тот же предел у `ElibraryHTTP.download()` (PDF с elibrary.ru): сначала по `Content-Length`, затем
  по фактически принятым байтам; ошибка — `ElibraryError` «Файл … слишком большой … Скачивание
  прервано, недокачанный файл удалён».
* Антибот-страницы («Вы точно человек?», Cloudflare challenge, `captcha` там, где ждали JSON/PDF) —
  `ExternalChallenge`, хост блокируется на 15 минут. Капчи не решаются и не обходятся.

### 7.1. `robots.txt`

* Проверяется для страниц и файлов на произвольных хостах: страницы издателей и
  `citation_fulltext_html_url`, все PDF (`try_pdf`), страницы КиберЛенинки. **Не** проверяется для
  JSON-API, предназначенных для программ: api.crossref.org, api.openalex.org, api.unpaywall.org,
  api.datacite.org, hdl.handle.net/api (и для `/api/search` КиберЛенинки, если пользователь сам его
  включил). Включается аргументом `robots=True` у `get_page`/`get_bytes`/`download`/`download_pdf`/
  `request`; проверяется **каждый шаг** перенаправления, до отправки запроса. Ответ из кэша не
  требует проверки (запрос не отправляется).
* Разбор — `urllib.robotparser` (группы, выбор группы по User-Agent: первое слово до `/` нашего
  UA, `elibrary-cli`, иначе `*`); сопоставление путей — по RFC 9309 (`RobotsRules.can_fetch`):
  `*` и `$` поддерживаются, побеждает самое длинное правило, при равной длине — `Allow` (сам urllib
  сравнивает буквальные префиксы по порядку и `Disallow: /article/n/*/pdf` не сработал бы).
  Особенность urllib: `Disallow: /search?` превращается в `/search` (чуть строже, чем написано).
* Ответы: 2xx — правила; 404 и прочие 4xx — ограничений нет; 401/403 — запрещено всё (как в urllib);
  429 и 5xx — «недоступен», запрещено всё (RFC 9309), помнится 10 минут; **сетевая ошибка** —
  единственный случай «fail open»: запрос разрешается, повтор через 10 минут; `robots.txt` больше
  512 КиБ — запрещено всё. Анти-бот страница вместо `robots.txt` — `ExternalChallenge`.
* Кэш — на origin (схема + хост + порт): в памяти и во внешнем кэше (`external-cache.sqlite3`,
  ключ `ROBOTS` + URL) на 24 часа; `ELIBRARY_REFRESH=1` — перечитать, `ELIBRARY_OFFLINE=1` — только
  кэш, без кэша ничего не запрещается (запросы всё равно не отправляются).
* Запрещённый адрес — `RobotsDisallowed` («robots.txt сайта <хост> запрещает автоматическую загрузку
  <URL> — адрес пропущен.»), в `attempts` — `skipped` с этим текстом; источник переходит к следующему
  кандидату.

  HTML со ссылкой `/download/…`), нужен ли POST формы `results` вместо GET, `file_article.asp` для

  стороннему коду, не наблюдалась.

* Unpaywall с настоящим e-mail (в тестах — сохранённый ответ исследования).
